## Implemented boundary

A native token identifies immutable staff + device. `company_id` is null on new tokens and is never rewritten by tenant routing. Each tenant route resolves its explicit company, checks active company and active membership, sets CompanyContext with the authenticated actor, and checks fresh canonical grants. Product reads use ProductPolicy::viewAny; customer reads require customers.view; bootstrap requires sales.invoice.create. Role labels never grant authorization. The request boundary clears CompanyContext and Spatie teams before and in finally, and refreshes permission metadata. No browser CSRF or CommandSessionGuard change.

Devices have durable user ownership. Existing unowned registrations are fail-closed, not silently claimed. Unknown/foreign UUIDs cannot be revoked; administrative cross-user revocation has no company-free capability. Concurrent initial claims use inserts, never ownership-changing upserts. Login checks fresh credentials under user row lock. Token issuance, recovery consumption, and device registration share a transaction. Lock order is user, active company/membership rows, device, token. Browser Fortify's controller is container-bound to a subclass that locks and refreshes the user before delegating its original validation/replacement/session logic. Both consumers serialize on the same user row. Challenge consumption deliberately precedes the issuance transaction: failures burn the challenge, but must not consume recovery codes or create devices/tokens.

Future financial writes must revalidate token, device, credential revision, active membership, and permissions inside the canonical business-event transaction. This slice implements no financial endpoints.
