## Custody and coherent generation

Historical encrypted application-state archives contain production .env. Treat them as secret-bearing: database/mail credentials and application keys may be inside. Separate backup-passphrase custody does not remove those secrets from the archive. Never activate archived credentials or rely on extracting .env as proof of independent application-key recovery. Retain applicable APP_KEY and APP_PREVIOUS_KEYS independently for every retained encrypted record/backup version. Do not rotate or generate keys during recovery.

Proposed cadence, pending Owner adoption and capacity/cost verification: daily coherent backup plus pre-release, pre-schema-change and pre-key-change points. Proposed retention: 7 daily, 4 weekly, 3 monthly; retain key versions for at least the lifetime of dependent records and backups. A coherent point needs transaction-consistent SQL and matching application/files/configuration, using a verified quiescence/snapshot procedure, not unrelated copies at different times. Record source capture time, completion, exact code SHA/build digest, component sizes/hashes, required key identifiers and custody verification. No secret values in manifests.

Independent off-host storage must survive primary-host loss, account compromise and suspension; its credentials/recovery path must not depend on that account. Verify downloaded ciphertext hashes using a trusted manifest digest conveyed independently. Verify backup passphrase recovery and application-key recovery separately with protected custody. Record last COMPLETE independently recoverable off-host point; incomplete points cannot advance freshness.

## Fail-closed sequence for an authorized rehearsal

1. Obtain explicit authorization identifying target, access-controlled operator/custodian, scope, allowed data and cleanup/evidence retention. Verify the trusted ENCRYPTED archive/component checksum before processing. Preserve source ciphertext unchanged.
2. Establish restricted, nonpublic scratch on an isolated recovery host before decrypting. Use encrypted ephemeral storage and exclusive access (POSIX directories0700/files0600, equivalent verified Windows ACLs). Apply and test actual ingress/egress restrictions: no production DB destination/aliases, SMTP, HTTP integrations, scheduled jobs or public ingress. Permit only the independently provisioned disposable local DB. Flags and declarations are not isolation evidence.
3. Decrypt/extract only as inert data inside that boundary. Validate archive members before extraction: refuse absolute/traversal paths, symlinks, hardlinks and special files. Never autoload or run archived application code. Quarantine every archived .env and stale bootstrap/cache configuration/routes/services/packages cache. Quarantine must be nonpublic, inaccessible to runtime and outside the active application root. Inspect secret-bearing configuration without copying its values into evidence.
4. Provision a newly verified dedicated disposable database and non-root identity with privileges restricted to that schema. The inspector currently accepts numeric local loopback only, schema accounting_p10_restore_<12hex>, user p10_restore_<12hex>. An independently issued protected ownership-proof file binds host, port, schema, user and nonce; metadata is not proof of server ownership. Independently verify server identity, effective grants and target emptiness/ownership using non-Artisan database tooling. Never overwrite production or any persistent schema.
5. Prepare a fresh isolated application root using trusted compatible code/build. Create isolated environment/configuration BEFORE bootstrap: explicit local DB destination and credentials, no archived DB URL/socket/read-write override, local URL/session/cache/storage, registration disabled, APP_DEBUG=false and mail array transport. Inspect config/database.php and all environment/process overrides for effective destination. The current queue configuration has no named null connection: explicitly define a rehearsal-only queue connection with driver null in trusted scratch configuration and select it; merely writing QUEUE_CONNECTION=null does not prove jobs disabled. Disable scheduler/workers and outbound integrations independently at the network layer. Do not copy this rehearsal configuration into production source.
6. Run the trusted dependency-free inspector from OUTSIDE scratch. It loads no Laravel/vendor/Artisan. Required options: --manifest=<path>, --manifest-sha256=<independently-trusted-64hex>, --expected-code=<reviewed-40hex>, --scratch=<inert-path>, --ownership-proof=<protected-path>, --target-host=<numeric-loopback>, --target-port=<port>, --target-schema=<owned-schema>, --target-user=<restricted-user>. Manifest version1 requires mode, point_id, captured_at, completed_at, off_host_verified_at (nullable), code_sha, build_sha256, schema, key_history_refs, config_ref and six ciphertext components: sql/code_build/private_files/public_assets/encrypted_records/configuration, each with file/bytes/sha256/point_id. Key references contain id/cipher only. Output exit1 refuses unsafe metadata; exit2 means INSPECTION_ONLY_BOOTSTRAP_BLOCKED, bootstrap_authorized=false. Windows ACLs, actual networking, DB ownership, key recovery and restoration remain NOT VERIFIED by this tool.
7. Independently verify effective fresh configuration, target connection/grants and actual network isolation BEFORE ANY Artisan, migration or application startup. Test local allowed connectivity and prohibited routes without contacting production services. Record sanitized firewall/namespace, process, destination and grant evidence. Recheck no stale cache or archived credentials are active. Stop on ambiguity.
8. Only after those checks, the separately authorized custodian temporarily injects applicable application keys through protected files or protected process custody. Never command-line arguments, shell history, logs or repository files. Recheck effective key identifiers without logging values. Import the decrypted, validated SQL file into the verified disposable schema using protected DB credential custody. NEVER import a .enc ciphertext file as SQL. Restore approved private/public files and verify their digests/build compatibility.

For historical lane, prove restored 80/61 counts, switch to reviewed target code/build as needed, then run only forward migrations and idempotent purchasing:bootstrap --all and documents:bootstrap --all. Verify expected83/63 and preserved historical rows. For current lane, verify recovery-point schema and code directly. ## Required negative cases and release gates

Synthetic tests cover metadata rejection and always-blocked bootstrap. Authorized rehearsal additionally proves wrong/missing backup passphrase and old application key, corrupted/missing components, incompatible code/build/schema, traversal/link members, production .env/stale caches, wrong/aliased DB destination, insufficient/wrong-owner grants, outbound integration/job/ingress attempts, partial import/restore interruption and cleanup failure. Missing evidence stays NOT RUN or NOT VERIFIED. Each failure stops bootstrap/cutover and preserves ciphertext.

Never execute migrate:fresh/refresh, db:wipe, destructive reseeding or schema rollback on persistent data. Deployment recovery retains forward schema history; validate compatible prior code/assets or use a reviewed forward repair. This runbook grants no production merge/deployment/DNS/custody authorization. Gate1 may accept source safety tooling; P10-G/customer readiness still requires independent acceptance of both real recovery proofs, approved account recovery delivery and off-host backup/key custody.
